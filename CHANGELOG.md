# Changelog

All notable changes to tripcurve. Dates are 2026. The licence is decided by the maintainer before release.

## 0.1.0 (unreleased)

**tripcurve 0.1.0 has not been released.** A bolt is one build step: B7 is build step 7. tripcurve is not published to npm. The source was pushed to https://github.com/naren-ambati/TripCurve on 2026-11-15, where the hosted workflow and the GitHub Action's self-test ran once and every job succeeded (B25). `package.json` is `"private": true` with `"license": "UNLICENSED"`. What is listed here is built and checked locally, bolt by bolt, from the record in `BUILD-NOTES.md`; what must be true before the maintainer's go is in `docs/release-checklist.md`.

### Added

- **B0, day-1 measurement (2026-11-11).** Measurement scripts (`measure/`) that time a server's idle close on 127.0.0.1 with a raw-socket client, and the first knowledge-base seeds: Node 22, 24 and 26, gunicorn 26 and 27 with the uvicorn worker, and uvicorn alone. A self-test catches mutated measurers. (`BUILD-NOTES.md`, "B0 Day-1 measurement"; `docs/research.md` section 13)
- **B1, the thin slice.** The pipeline (parse, link, resolve, evaluate, report), the Kubernetes and Node readers, the ALB Ingress link, rule T1 and the human report with provenance on every value, checked by the demo's `web` golden. Input limits are derived and recorded (`docs/limits.md`). Seven fix passes followed the review. (`BUILD-NOTES.md`, "B1 Thin slice")
- **B2, Python servers and the worker model.** gunicorn and uvicorn command lines, `GUNICORN_CMD_ARGS` and `gunicorn.conf.py` (read, never run), the worker model resolved before any keep-alive default (the sync worker is N/A for T1), measured setting precedence, and version pins from `requirements*.txt`, `pyproject.toml`, `poetry.lock` or `uv.lock`. (`BUILD-NOTES.md`, "B2 Python servers and the worker model")
- **B3, Node version edge cases.** Version intervals, VERSION-DEPENDENT results, explicit `keepAliveTimeout` measured (the extra second predates the buffer property), the `headersTimeout` trap, and every printed basis written from recorded runs. (`BUILD-NOTES.md`, "B3 Node version edge cases and the buffer measurement"; `docs/research.md` section 14)
- **B4, the shutdown chain: T2 and T3.** preStop, in-process drains (lightship, terminus, SIGTERM handlers, read by an allow-list), the grace period, gunicorn and uvicorn graceful-timeout ceilings (measured), `longest_request_s` and `drain.in_process_s` declarations. (`BUILD-NOTES.md`, "B4 Shutdown chain T2 and T3")
- **B5, Terraform and T4.** A bounded Terraform reader with no HCL dependency, Terraform JSON and `terraform show -json`, event source mapping links, rule T4 (a credited port of cdk-nag's rule), and dated lookups of the AWS defaults. (`BUILD-NOTES.md`, "B5 Terraform and T4"; `docs/lookups-b5.txt`)
- **B6, waivers, summary variants, exit codes and `--explain`.** Inline and `tripcurve.yaml` waivers with one validator, UTC expiry, the `No failures:` ending, every exit code, and `--explain T1` to `T4` with vendor quotes. (`BUILD-NOTES.md`, "B6 Waivers, summary variants, exit codes and explain")
- **B7, JSON and SARIF.** JSON and SARIF renderers from one report model, suppressions, a run-level warning so a SARIF-only gate cannot see a clean run when the run is not clean, and a subset SARIF validator. (`BUILD-NOTES.md`, "B7 JSON and SARIF")
- **B8, measurement lanes.** `npm run verify:measure` (pinned lane) and `node measure/lanes.mjs latest`: every entry has a script run or a stated reason, nothing is retried, and a lookup failure stops the lane. (`BUILD-NOTES.md`, "B8 Measurement harness lanes")
- **B9, the GitHub Action.** A composite Action built from its own checkout, with pinned third-party SHAs, inputs passed as environment variables, and the SARIF upload disabled. When it was written it had not run on GitHub; it first ran on 2026-11-15 (B25). (`BUILD-NOTES.md`, "B9 GitHub Action"; `docs/action.md`)
- **B10, the demo repository and end-to-end test.** `demo/` and `demo-fixed/` with byte-exact expected output, and a timed check that is the last step of `npm run verify`. (`BUILD-NOTES.md`, "B10 Demo repository and end-to-end test")
- **B11, not used.** The build plan skips the number 11; no change carries it. (`docs/release-checklist.md`, "Reviews")
- **B12, SAM and CloudFormation.** A reader for SAM and CloudFormation templates into the same model as Terraform, so T4 is unchanged, with documented defaults. (`BUILD-NOTES.md`, "B12 SAM and CloudFormation")
- **B13, old-Node measurement: attempted, nothing measured** (status as of 2026-11-12). Node 10, 12 and 13 have no arm64 macOS build and this host has no x64 runtime, because Rosetta 2 is absent. The three `node-headers-trap-*` entries keep the basis "from changelogs, not measured" and stay DEFERRED (B13). Measuring them needs Rosetta 2 installed by the maintainer, or an x64 or Linux host. (`src/kb/data/node-idle-close.json`; `docs/how-defaults-were-measured.md`)
- **B14, the real-repository check (2026-11-12).** Trimmed copies of four public MIT repositories (`peermetrics/peermetrics`, `akhileshmishrabiz/DevOpsDojo`, `sorah/publikes`, `DanielDaCosta/apiGateway-sqs-lambda`), each with its upstream licence file and a NOTICE (source URL, commit, date), run through the built command with every result judged against the real files. No false positive, false negative or crash was found; no run reaches PASS, because real files leave values open (`envFrom`, an image no file builds, the assumed ALB idle timeout, Terraform split across files). Each gap is a documented known limit (`docs/limits.md`, "Real-repository check"). Shapes with no qualifying repository (gunicorn with the uvicorn worker or `--threads`, Terraform `aws_lb`, SAM with an SQS event, a real preStop hook with a grace period) are covered by named synthetic fixtures. (`test/fixtures/real/README.md`; `test/e2e/real-repos.e2e.test.ts`)
- **B15, documentation and release checks.** The README, the rules reference, how defaults were measured, how to add a knowledge-base entry, CI and SARIF, the security note, this changelog and the release checklist (`docs/release-checklist.md`), with a test that checks the docs' diagrams, quotes and sourced numbers.
- **B16, release fixes (2026-11-12).** An npm `overrides` entry pins `minimatch` to 11.0.8, so `npm audit` finds 0 vulnerabilities (see the release checklist row 5b for the tarball caveat) (the lockfile then had 123 packages); the full test suite, the build and the demo pass on Node 22.12.0, 22.23.5, 24.22.3 and 26.13.1, and Node 20 and 18 print the fixed unsupported-Node message and exit 2; the scaling helper no longer reads a one-off cost jump on Node 24 as quadratic work; the unchecked-reason order no longer depends on the locale; a one-off check against the official SARIF 2.1.0 schema passed on every golden and the demo output; the small open questions were decided (`docs/release-checklist.md`, "Decided on 2026-11-12"); `docs/security.md` says how to report a vulnerability. (`docs/release-checklist.md`; `docs/release-check-run-b16.txt`; `docs/limits.md`, "The minimatch override")
- **B17, the fixes the real-repository check found (2026-11-12; delegated by the maintainer).** (1) A Terraform reference links within its own folder, because Terraform reads every file of a folder as one module (it never links into a subfolder, a parent folder or a `module` block; duplicates, variables, `count`, `for_each` and override files stay UNRESOLVED), which widens the earlier rule that a reference links only within "the same file". (2) Integer arithmetic on literals (`60 + (30 * 6)`) is read exactly, and the expression is printed beside the result. (3) T4 is a FAIL when visibility is below 6 x the function timeout even when the batching window is not set, because a window can only raise the need. (4) A `--config` path outside the checked folder is printed as typed, not as an absolute path. (5) The hint for a container whose program is not identified no longer assumes Node. With these, the `sorah/publikes` copy is a PASS and the `DanielDaCosta/apiGateway-sqs-lambda` copy a FAIL; this supersedes the B14 statement that no run reaches PASS. (`docs/lookups-b17.txt`; `docs/limits.md`, "The link between mapping, queue and function"; `test/fixtures/real/README.md`)
- **B18, the lane runner flushes its output before it exits (2026-11-13).** `measure/lib/exit-after-flush.mjs` writes an empty chunk to standard output, then to standard error, and exits in the last callback, so every earlier write has reached the operating system before the process ends. The CLI itself was already safe: it sets `process.exitCode` and never calls `process.exit`. (`BUILD-NOTES.md`, "B18 Flush before exit")
- **B19, ready for the first hosted run (2026-11-13).** The Action gets an opt-in input `upload-sarif` (default `false`); the upload step runs only when it is `true` and a SARIF file was written, and its condition uses `always()` so it also runs after a failed check. `.github/workflows/verify.yml` becomes a matrix (Ubuntu with Node 22.12.0, 24 and 26; macOS with Node 22.12.0). A new `.github/workflows/action-selftest.yml` runs the Action on `demo-fixed` (clean), `demo` (failing) and `demo` with the upload (public repositories only). `action/dry-run.sh` simulates the three scenarios and never the upload. When it was written nothing had run on GitHub; the first runs were on 2026-11-15 (B25). (`docs/action.md`; `docs/lookups-b19.txt`; `docs/release-checklist.md`, rows 12 to 14)
- **B20, publication clean-up (2026-11-14).** Every file that would be published stands on its own: design-process references, home and scratch paths and personal identifiers are removed, 12 measurement records say `<repo>` instead of an absolute path, and `package.json` carries `repository`, `homepage`, `bugs`, `keywords` and `author` (`private: true` and `license: UNLICENSED` unchanged). A test (`test/docs/publication.test.ts`) scans every published file, and the local export script refuses to run on any hit. No behaviour changed: the CLI output is byte-identical to before. (`BUILD-NOTES.md`, "B20 Publication clean-up")
- **B21, fixes from the hardcore local testing (2026-11-14).**
  - Reading a Node or TypeScript source no longer takes quadratic time in its statements (a 400 KB file of repeated declarations took 2.3 s and a 1.6 MB one 34 s; a 4.8 MB one did not finish): the export keyword is read from the syntax instead of asking the TypeScript binder. A source with more than 500,000 syntax nodes is listed under "Files not checked" as `source-too-large`, and what depended on it is UNRESOLVED. Numbers are in `docs/limits.md`.
  - A Kubernetes manifest written as JSON, with quoted keys or as a one-line flow mapping is now read like its block-style twin; before, it was silently skipped and the run said "All checks passed". A broken or truncated manifest in these styles is listed under "Files not checked".
  - A syntax error in a linked source is listed as `source-parse-error` with its first line, and T1 says "the source could not be parsed".
  - A shrinkwrap file replaces the lock file in the package and pins the tree a person gets. It does not carry the `minimatch` override: a fresh project that takes the packed tarball sees 4 moderate audit advisories (details and options in `docs/limits.md`). The tarball no longer holds `.js.map` files.
  - The automation files run on pushes to `main` and on every pull request, so a same-repository pull request runs once.
  - `node measure/lanes.mjs <lane> --only=<id>` on an entry with a stated reason or a deferral prints `NOT RUN` and exits 2, not `LANE FAIL`.
  - A Kubernetes manifest file that is a list of objects at its root (a JSON array, a flow sequence, a block list) is read element by element, never skipped; an element that is not an object is listed under "Files not checked".
  - Imports of files that do not exist no longer take quadratic time (2.4 MB of them took 28.1 s, now 1.07 s; `docs/limits.md`).
  - The "Files not checked" line for a source syntax error carries its line; a source that could not be read no longer advises "link an entry file" but names the fix; the build empties `dist/` first.
  - The docs now say the audit is clean for the checkout only, and NOT clean for a fresh project that takes the packed tarball (row 5b of the checklist).
- **B22, documentation corrections and two small code items (2026-11-14).** A `check` subcommand is no longer written anywhere: the command has none, and a test fails on a published text that shows one. The release checklist and this changelog carry re-run, dated figures and one entry per bolt, B0 to B22. The tarball audit caveat is stated in `docs/security.md`, `docs/release-checklist.md` (row 5b) and here: the audit is clean for a clone followed by `npm ci` and for the tree that the hosted workflows would install (they first ran later, on 2026-11-15, B25), and NOT clean for a fresh install of the packed tarball; the package is private and not published to npm. The demo README says where the `preStop` block goes (reproduced literally in a copy). A manifest-shaped document whose `apiVersion` is not text is listed as not identified in every form, as it is in plain YAML, and a root list with no object of text `kind` is listed inside a stream as it was alone. A `--config` file that was never opened no longer says "at line 1" in the human report (JSON and SARIF keep the number the contract requires), and with nothing checked the human summary carries the same unresolved count as JSON. (`BUILD-NOTES.md`, "B22"; `docs/limits.md`, "B22")
- **B23, test evidence (2026-11-15).** The README gains a "Test evidence" section: a table of every check run on a fresh checkout after the black-box testing, with verbatim screenshots under `docs/screenshots/` and the full transcripts under `docs/evidence/` (the verify summary, the demo before and after the fix, the four real repositories, the JSON and SARIF outputs and the official-schema validation, the Node release matrix, the dependency scan and the tarball listing, the Action's dry runs, the measurement lanes' case list). `docs/evidence/black-box-testing.md` records what the two testing passes ran. The README's no-badge rule now allows a local screenshot under `docs/screenshots/` and still refuses any other image. (`BUILD-NOTES.md`, "B23")
- **B24, no stack trace when the reader of the output closes early (2026-11-14).** `tripcurve demo | head -1` printed an unhandled `write EPIPE` trace from `dist/cli/main.js`. A closed pipe is now a normal condition: tripcurve stops writing, prints nothing further and exits with the code the run computed (1 when it was not yet known). Output and exit codes are otherwise unchanged. Node's behaviour is quoted in `docs/lookups-b24.txt`; the regression test is `test/e2e/closed-pipe.e2e.test.ts`.
- **B25, the first hosted runs recorded (2026-11-15).** The source was pushed to https://github.com/naren-ambati/TripCurve on 2026-11-15 as two commits (`6809df0`, `cf55f77`); the public history starts at that export and does not include the earlier private history. GitHub ran both workflows on that push, the repository's only two runs, and every job passed on that first attempt: `verify` (run 43682221175; Ubuntu with Node 22.12.0, 24 and 26 and macOS with Node 22.12.0, the first run of the suite on Linux) and `action-selftest` (run 43682221183; `clean`, `failing` and `upload`). The `upload` job sent the demo's SARIF to code scanning: 6 results, 7 rules and six open alerts. ### Known limits of this release candidate

- Measurements were made on one macOS arm64 laptop, on localhost. No ALB, cluster or Linux host was involved. (`docs/how-defaults-were-measured.md`)
- The "6 of 26" reproduction was Node 22.23 and gunicorn with uvicorn through toxiproxy, not an ALB. (`docs/research.md` section 12)
- The old-Node `headersTimeout` entries are not measured. (above)
- `npm run verify` validates SARIF with a subset validator; the official schema was applied once, on 2026-11-12, and is not vendored. (`docs/ci-and-sarif.md`)
- Locally, nothing was run on Linux; the hosted Linux run of 2026-11-15 ran the verify suite (B25). (`docs/release-checklist.md`, "Platform audit of `src/`")
- The Action and the hosted workflow had not run on GitHub when B24 was built; they ran once on 2026-11-15 and every job succeeded (B25), and they were not tried on a pull request, from a fork or in a private repository. (`docs/action.md`)
- `npm audit` is clean only because of the `minimatch` override, which was checked by one call and the test suite, not on every `ts-morph` code path (see the release checklist row 5b for the tarball caveat). (`docs/release-checklist.md`)
- `npm audit` is NOT clean for a fresh install of the packed tarball: npm `overrides` do not ship, and ts-morph 28.0.0 (the newest) pulls `minimatch` 10.2.6 (4 moderate advisories). The package is private and not published to npm, so no such consumer exists today; it must be closed before any npm publish. (`docs/release-checklist.md`, row 5b)
